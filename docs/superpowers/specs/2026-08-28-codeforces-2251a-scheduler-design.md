# Codeforces 2251A 交互式调度器设计

## 目标

实现一个可直接提交到 Codeforces 的 C++17 单文件交互式调度器。首要目标是严格遵守交互协议并完成所有请求；在此基础上，通过云端负载均衡、截止时间优先和自适应批处理提高吞吐率并降低 TDR、TPOT。

最终提交文件为 `tmp/tmp-8-28/cf2251a.cpp`。测试工具可以单独存在，但提交时只需要该源文件。

## 方案选择

采用事件驱动的在线启发式调度，而不预测未知请求和未知输出长度。

- 不采用纯单请求 FIFO：实现简单但不能有效摊薄调度开销和链路延迟。
- 不采用完整离散事件前瞻搜索：未来到达和输出长度不可见，搜索成本高且容易与交互器状态产生偏差。
- 采用状态机加动态批处理：只依据已到达事件维护真实状态，并利用任务时间表、SLO 和当前队列选择任务。这种方案兼顾协议安全、运行效率和得分潜力。

## 单文件结构

源文件内部按职责划分以下组件：

1. `TimeTable`：读取六列耗时数据，预计算批大小 `1..2000` 的分段线性插值结果。
2. `Request`：保存请求状态、固定云服务器、输入长度、到达时间、最近 Token 时间和 Prefill 切片进度。
3. `Scheduler`：解析完整事件帧、维护服务器忙闲状态和在途任务、生成本轮合法任务。
4. 调度策略函数：分别为边缘服务器和每台云服务器构造候选批次并计算优先级。

这些组件全部保留在一个 `.cpp` 文件中，避免提交时依赖其他文件。

## 状态与事件处理

请求严格沿以下状态流转：

```text
ARR -> P PRE -> PRE UP -> P PROC piece(s) -> PRE DOWN -> P POST
    -> D PRE -> DEC UP -> D PROC -> DEC DOWN -> D POST
    -> FIN 或下一轮 D PRE
```

程序先读取一个帧的所有事件，再统一调度。同帧中的 `FIN` 集合优先用于过滤已完成请求，避免在最终 `D POST` 的 `TDN` 后错误启动下一轮。

每台服务器只保存一个正在执行的任务。输出任务时立即标记服务器忙；只有收到对应 `TDN` 才重新标记为空闲。传输不自行模拟完成时间，只记录是否存在在途传输并等待 `XDN`。

## 调度策略

### 云服务器分配

`P PRE` 为新请求选择估计负载最小的云服务器。负载由当前运行任务、已经就绪的 Prefill/Decode 计算和该服务器上的活跃请求数共同组成。由于输出长度不可见，不使用剩余 Token 数估计。

### 动态批处理

启动时根据任务时间表、调度开销和网络参数估算吞吐最优批大小。运行时按以下规则截断：

- 达到目标批大小时立即调度；
- 最老请求接近 `SLO1` 或 `SLO2` 时立即调度现有批次；
- 如果继续等待可能没有下一事件，则至少调度一个请求，防止 stuck；
- `D PRE` 和 `D POST` 可跨云服务器合批，`D PROC` 只在同一云服务器内合批。

边缘服务器候选任务按截止时间和阶段收益排序。`P POST` 直接结束 TDR，`D POST` 直接产生 Token，因此逾期候选优先；其余候选通过等待年龄保证不会饥饿。

### Prefill 切片

默认执行完整 `P PROC [0,num_layers)`。只有完整 Prefill 预计长时间阻塞已有 Decode 请求时才切片；切片必须连续、无空洞，并限制切片数量，避免重复支付过多调度开销 `S`。

第一版实现将使用完整 Prefill，以降低协议风险；状态结构保留合法切片进度，后续可在测试通过后启用保守切片。

## 防错与降级

- 所有分组成员必须处于完全相同的下一阶段，且没有正在执行的任务。
- `D PROC` 分组额外检查成员的固定云服务器相同。
- 每轮输出最多为 `K+1` 个任务，同一服务器最多一个。
- 输入 EOF 或交互器关闭时立即正常退出。
- 每次输出完整响应后显式 `flush`。
- 如果高分策略无法组成理想批次，但当前无可靠未来事件，则降级为合法的单请求任务。

## 测试与验收

测试分为三层：

1. 编译检查：使用 `g++ -std=c++17 -O2 -pipe -Wall -Wextra -Wshadow`。
2. 纯函数测试：验证任务时间表插值、端点外推、批大小选择和优先级比较。
3. 协议回放：使用题面 Example 1 的输入回放，逐行核对程序产生的任务是否与事件依赖一致，并确认最终读到 `END` 后退出。

题面样例是交互记录，不能像普通非交互题一样把完整 Input 一次性重定向后直接与固定 Output 比较。测试器需要在每一帧后读取并校验程序响应，再发送下一帧。

完成标准：编译无警告；单元测试通过；Example 1 交互回放正常结束；额外覆盖多云服务器合批、同帧 `TDN+FIN`、空闲防 stuck 和 `num_layers=1`。
